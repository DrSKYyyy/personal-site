# 项目规则

## 版本与效果一致性报告规则

1. **版本冲突必须第一时间汇报**：当安装或使用某个库/依赖时，如果实际安装的版本与官方示例、Magic UI 或其他参考来源指定的版本不一致（包括大版本差异），必须在操作前向用户报告差异和可能的影响。

2. **效果不一致必须汇报**：当实现某个功能/组件后，如果实际效果与参考源（如 Magic UI 官网展示、设计稿等）存在肉眼可见的差异，必须在交付时明确说明差异点、原因（如版本差异、框架限制、浏览器兼容性等）。

3. **禁止隐瞒或弱化问题**：出现效果不一致时，绝对不允许说"任务完成"而不提及问题。必须如实汇报，由用户决定是否接受当前效果或采取修复方案。
