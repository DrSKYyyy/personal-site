## 前言

&emsp;&emsp;我一直对KTV有阴影。尝试强迫自己去了几次但于事无补。我想也许可以先借助AI工具，克隆自己的声音，然后让AI替我唱各种歌，先听听效果，慢慢克服这种恐惧。

&emsp;&emsp;目标很明确：**用我的声音唱歌**。但通往这个目标的路，比我想象的曲折得多。这篇文章记录了整整一天从零开始的完整历程——包括所有走错的弯路、踩过的坑，以及最终的解决方案。如果你也想做同样的事，希望这篇文章能帮你省下大把时间。

## 工具选择：为什么是 GPT-SoVITS + RVC？

&emsp;&emsp;目前主流的AI语音克隆方案主要有两种：

| 方案 | 原理 | 适合场景 |
|------|------|---------|
| **GPT-SoVITS** | 文本转语音（TTS），输入文字，输出语音 | 朗读、配音 |
| **RVC** | 变声转换，将一段音频的音色替换成目标音色 | 唱歌、实时变声 |

&emsp;&emsp;如果你只是想唱歌，**直接选RVC**。我一开始不清楚，走了GPT-SoVITS的路，其实它的强项是"说话"而不是"唱歌"。当然，GPT-SoVITS训练出来的SoVITS模型（音色模型）是可以复用的，所以也不算完全白费。

## 环境配置：最大的坑

### 坑1：不要手动配环境，用整合包

&emsp;&emsp;一开始我试图从GitHub克隆源码，手动用Conda创建环境、安装依赖。这是**第一个大坑**。

```
conda create -n GPTSoVits python=3.9
pip install -r requirements.txt
```

&emsp;&emsp;看起来简单，实际上会遇到各种版本冲突：

- **CUDA版本不匹配**：你的PyTorch需要和CUDA驱动对应，否则找不到GPU
- **Jinja2和MarkupSafe兼容性问题**：Gradio 4.44对Jinja2版本有严格要求，装错了启动就报 `TypeError: unhashable type: 'dict'`
- **网络问题**：国内下载PyTorch和HuggingFace模型需要科学上网

**解决方案**：直接下载**官方整合包**（Integrated Package）。整合包已经打包好了Python运行环境 + 所有依赖 + 预训练模型，解压即用。GPT-SoVITS的整合包在GitHub Releases页面可以找到（由花儿不哭大佬维护），国内用户可以使用ModelScope（魔搭）的镜像直链下载，速度很快，不需要VPN。

### 坑2：沙箱环境的限制

&emsp;&emsp;我是在Trae IDE中操作的。Trae有一个沙箱安全机制，会阻止对某些目录的文件写入操作。这导致下载的训练模型权重无法保存到不在工作区目录下的盘上。

**表现**：训练日志显示"模型已保存"，但文件实际不存在。

**解决方案**：直接在本地PowerShell（不要通过IDE的终端）中运行命令，绕开沙箱限制。

## 第一阶段：下载和解压

&emsp;&emsp;GPT-SoVITS v2pro整合包大约8GB，下载需要一些时间。推荐使用BITS传输（Windows自带）或直接浏览器下载。

&emsp;&emsp;下载后用Bandizip或7-Zip解压。解压后目录结构如下：

```
GPT-SoVITS-v2pro/
├── runtime/          # 预装Python环境和依赖
├── GPT_SoVITS/       # 核心模型代码
├── tools/            # 音频处理工具
├── webui.py          # Web界面启动脚本
├── go-webui.bat      # Windows一键启动
└── ...
```

&emsp;&emsp;最令人欣慰的是，`runtime/`目录里自带了完整的Python 3.9环境和所有依赖，**不需要自己安装任何包**。

## 第二阶段：录制声音样本

&emsp;&emsp;这一步直接决定了最终效果。我一开始低估了它的重要性。

**我的做法**：用手机在安静房间里录了约7分钟的朗读，内容是《最重要的事只有一件事》这本书的节选。

**关键要求**：

| 要求 | 说明 |
|------|------|
| 时长 | 5-10分钟即可 |
| 环境 | 安静，无背景噪音 |
| 语气 | **自然平静**，不要加太多情感 |
| 内容 | 多样化的文字（小说、新闻、散文） |

> ⚠️ **血的教训**：录制时嗓子状态很重要！我当时嗓子有点干哑，结果训练出来的模型把这种嘶哑放大成了"气泡音"，后期怎么调参数都去不掉。建议在状态好的时候重新录制，保证声音干净饱满。

## 第三阶段：数据预处理

&emsp;&emsp;这是GPT-SoVITS流程中最繁琐但最关键的一步。在WebUI的 **Tab 0 - 前置数据集获取工具** 中操作：

### 3.1 语音切片

&emsp;&emsp;将长音频切成10-15秒的短片段。输入你的录音文件路径，工具会自动切片。
```
输入: D:\my_voice\my_voice.wav
输出: D:\my_voice\sliced\ (自动创建)
```
&emsp;&emsp;我的7分钟录音被切成了100段。

### 3.2 语音识别（ASR）

&emsp;&emsp;AI自动识别每段音频对应的文字。这一步使用了FunASR模型（需要从ModelScope下载）。

**遇到的坑**：ModelScope在下载模型时需要在用户目录下创建 `.modelscope` 凭证文件夹，如果权限不足会报错 `PermissionError`。

**解决方案**：设置环境变量 `MODELSCOPE_CREDENTIALS_PATH` 指向一个有写入权限的路径。

### 3.3 校对标注

&emsp;&emsp;AI识别出来的文字可能有错误，需要手动校对。比如我的音频中"共享美好时光"被识别成了"共享美好人"。这一步确实烦人，但如果识别质量较高，也可以跳过。

## 第四阶段：训练

### 4.1 一键三连

&emsp;&emsp;在 **Tab 1A - 训练集格式化工具** 中，设置实验名称、输入标注文件路径和音频文件夹路径，点击"一键三连"。这一步会自动完成：重采样 → 特征提取 → 配置文件生成。

### 4.2 SoVITS + GPT 双模型训练

&emsp;&emsp;GPT-SoVITS会训练**两个模型**：

| 模型 | 类比 | 职责 |
|------|------|------|
| **GPT** 🧠 | 大脑 | 处理文字内容，决定语调、停顿、节奏 |
| **SoVITS** 🎤 | 声带 | 学习音色，让声音听起来像你 |

**遇到的坑**：

1. **显存不足（OOM）**：默认batch_size对6GB显存的RTX 3060来说太大了。把 `batch_size` 从3降到1，并开启 `grad_ckpt`（梯度检查点）来减少显存占用。

2. **保存路径不存在**：训练脚本保存模型时需要 `logs_s2_v2Pro` 子目录，脚本不会自动创建。在启动训练前手动创建即可。

3. **文件路径分隔符混用**：Windows下用反斜杠 `\`，但代码中可能混用了正斜杠 `/`，导致文件找不到。用 `os.path.join()` 统一处理。

### 4.3 训练耗时参考

| 模型 | 轮次 | 时间（RTX 3060 6GB） |
|------|------|---------------------|
| SoVITS | 8 epochs | 约15分钟 |
| GPT | 20 epochs | 约10分钟 |

## 第五阶段：测试TTS——失望

&emsp;&emsp;训练完后，在 **1C - 推理** 页面加载模型，输入文字合成语音。但结果很不理想：

- **电音/气泡音**：模型学到了我嗓子嘶哑的特征，并放大成了明显的颤音
- **文字对不上**：参考音频和参考文本必须一字不差，否则AI会乱生成
- **长度不对**：生成的语音会从中间截断或重复开头

&emsp;&emsp;这些问题的根源：

1. TTS本身就很敏感，参数调优门槛高
2. **录音质量**是决定性因素（我的录音嗓子状态不好）
3. GPT-SoVITS的TTS主要用于"说话"，唱歌效果有限

## 第六阶段：转向RVC——柳暗花明

&emsp;&emsp;既然TTS路线走不通，那就换**RVC（Retrieval-based Voice Conversion）**。RVC的思路非常简单：找一首别人唱的歌 → 把你的音色替换上去 → 保留原歌的旋律和节奏。

&emsp;&emsp;而且好消息是：**SoVITS模型不能直接用**，但之前切片好的100段音频可以直接用来训练RVC模型，不用重新录制！

### 下载RVC整合包

&emsp;&emsp;同样使用花儿不哭大佬的RVC整合包，从ModelScope下载：
```
https://www.modelscope.cn/models/FlowerCry/rvc-windows-packages/...
```

&emsp;&emsp;解压后目录结构清晰：
```
RVC20240604Nvidia/
├── runtime/          # Python环境
├── assets/           # 预训练模型
├── logs/             # 训练日志和模型输出
├── opt/              # 用户数据目录
├── go-web.bat        # 启动脚本
└── infer-web.py      # WebUI
```

### RVC训练

&emsp;&emsp;RVC的WebUI界面非常简洁，分为三个步骤：

1. **Step 1 — 实验配置**：设置实验名、采样率（选40k）、音高指导（唱歌选True）、版本（v2）
2. **Step 2a — 处理数据**：填写训练音频文件夹路径，点击处理
3. **Step 2b — 特征提取**：选 `rmvpe_gpu` 音高提取算法（效果最好），点击提取
4. **Step 3 — 开始训练**：总轮数20，保存频率5，点击一键训练

&emsp;&emsp;RVC训练比GPT-SoVITS快得多，100段音频只要**5-10分钟**就完成了20轮训练。

### 变声唱歌

&emsp;&emsp;训练完成后，切换到 **模型推理** 标签页：

1. 选择训练好的模型
2. 先通过UVR5将歌曲的人声和伴奏分离
3. 对人声部分进行变声转换
4. 转换后的音频 + 原伴奏 = 你用自己声音唱的歌

**参数调优经验**：

| 参数 | 推荐值 | 说明 |
|------|--------|------|
| 变调 | 0（同性） | 男变女+12，女变男-12 |
| 保护清辅音 | 0.2 | 防止电音，拉满0.5不开启 |
| 音量包络混合 | 0.25 | 保留原唱情感 |
| 滤波半径 | 3 | 减少毛刺感 |
| 检索比例 | 0.7 | 音色相似度 |

## 最终效果

&emsp;&emsp;虽然因为录音质量的原因，生成的音频还有轻微的气泡音，但已经能清晰地听出是自己的音色了。录音质量是当前最大的瓶颈——等嗓子状态好了重新录一次，效果会明显改善。

## 关键教训总结

### 1. 录音质量 > 一切

&emsp;&emsp;AI声音克隆的效果**70%取决于录音质量，30%取决于训练参数**。嗓子状态、环境噪音、录音设备的差异会直接体现在最终效果中。录10分钟高质量音频，胜过录1小时嘈杂音频。

### 2. 用整合包，别自己配环境

&emsp;&emsp;开源项目的依赖管理是最大的陷阱。整合包虽然体积大（7-8GB），但解压即用，帮你省去无数debug时间。

### 3. 唱歌用RVC，说话用GPT-SoVITS

&emsp;&emsp;这两个工具的分工不同：
- **GPT-SoVITS** = 文字转语音（TTS），适合朗读、配音
- **RVC** = 音色转换，适合唱歌、变声

### 4. 弯路最有价值

&emsp;&emsp;今天虽然绕了很多路，但正是这些弯路让我深入理解了AI语音克隆的完整链路——从数据采集、预处理、模型训练到推理部署。下次再做，从下载到出结果可能只要30分钟。
