# 层级切换系统

---

## 为什么需要层级切换

2D 游戏显示出来全部是平面，没有真正的"高度"。但 RPG 游戏中经常有角色走上山坡、登上高台等场景——这就需要通过**排序层级（Sorting Order）的切换**来模拟高度的效果。

**核心思路**：当角色走到楼梯/山坡入口时，通过触发器改变角色的 Sorting Order，将角色"渲染到"更高的层级上，同时关闭高层的碰撞体，让角色能够"走上去"。反之，从高处下来时恢复原状。

---

## 入口和出口的设计思路

整个系统由两个脚本配合完成：[[脚本_Elevation_Entry_Exit]]

### 入口（Entry）—— 走上高处的触发点

- 在楼梯尽头放置一个**触发器**作为入口
- 进入时：提高玩家的 Sorting Order + 关闭高地形的碰撞体 + 开启边界碰撞体

### 出口（Exit）—— 从高处下来的触发点

- 在楼梯起点放置一个**触发器**作为出口
- 进入时：恢复玩家的 Sorting Order + 开启高地形的碰撞体 + 关闭边界碰撞体

---

## 具体操作步骤

### 1. 创建入口触发器

1. 在低碰撞层（Collision-Low）下创建一个**方盒碰撞器（Box Collider 2D）**
2. 放置在楼梯的尽头（高处），形状设置成一条很细的矩形，像一条线一样
3. 勾选 **Is Trigger**（触发器模式），这样物体可以穿过去但会触发事件
   - 触发器就像一个感应区域，像红外光一样的效果——物体可以穿过，但会触发代码逻辑

### 2. 创建出口触发器

1. 新建一个层级专门用来放置出口（可以放在低碰撞层下面作为子物体，方便整理）
2. 放置在楼梯的开始处（低处）
3. 同样使用 Box Collider 2D，设置为触发器

> 入口在楼梯尽头，出口在楼梯开始。如果没有完全走过楼梯，其实是不会真正进入另一层的——必须走完整段楼梯触发出口才能恢复。

### 3. 创建边界层

因为层级切换的逻辑是：**将玩家的显示层拉高，然后取消高地形的碰撞体**。但一旦高地形的碰撞体被取消，玩家就可以直接从山上走下来——2D 游戏就是这样，没有真正的"墙壁"可以挡住。

解决方案：
1. 新建一个边界图层，专门用来挡住从高处的边缘
2. 使用平整的瓦块在高处边缘围上一圈
3. 将瓦块的透明度设为 0，伪装起来（玩家看不到）
4. 边界碰撞体的开关由入口/出口脚本控制

### 4. 添加脚本

1. 在入口触发器对象上挂载 `Elevation_Entry` 脚本
2. 在出口触发器对象上挂载 `Elevation_Exit` 脚本
3. 记得在 Inspector 中将对应的碰撞体数组拖入脚本的接口位置
   - 把需要开关的高地形碰撞体拖入 `mountainColliders`
   - 把边界碰撞体拖入 `boundaryColliders`

---

## 脚本逻辑说明

### Entry（入口脚本）做了什么？

当玩家进入入口触发器时：
1. 遍历所有 `mountainColliders`，将它们逐个**禁用**（`enabled = false`）
2. 遍历所有 `boundaryColliders`，将它们逐个**启用**（`enabled = true`）
3. 将玩家的 SpriteRenderer 的 Sorting Order **设为较高值**（比如 15），让玩家渲染在高地形之上

### Exit（出口脚本）做了什么？

当玩家进入出口触发器时：
1. 遍历所有 `mountainColliders`，将它们逐个**启用**（`enabled = true`）
2. 遍历所有 `boundaryColliders`，将它们逐个**禁用**（`enabled = false`）
3. 将玩家的 SpriteRenderer 的 Sorting Order **恢复为正常值**（比如 10）

---

## 整体工作流程

```
玩家在低处 → 走到楼梯尽头 → 触发 Entry
  → 高地形碰撞体关闭 → 玩家可以"走上去"
  → 边界碰撞体开启 → 防止从高处边缘掉落
  → 玩家 Sorting Order 提高 → 显示在高地形之上

玩家在高处 → 走回楼梯起点 → 触发 Exit
  → 高地形碰撞体恢复 → 地形恢复正常
  → 边界碰撞体关闭 → 不再需要边界
  → 玩家 Sorting Order 恢复 → 显示恢复正常
```
