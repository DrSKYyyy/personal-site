# 动画状态机逻辑

本文档深入解释 Unity Animator 中动画过渡的执行规则，帮助你理解"为什么动画有时不按预期切换"。

---

## 规则一：无条件过渡 ≠ 立即过渡

一个从状态 A 到状态 B、**没有条件**的过渡，并不是"立刻切换"。它的真实含义是：**"状态 A 播放完毕后，自动进入状态 B"**。

- 为什么不会立即中断？因为这个过渡有一个隐藏的默认设置：**`Has Exit Time`（有退出时间）默认是勾选的**。
- `Has Exit Time` 的意思是：**必须等待当前动画播放到"退出标记"位置，才允许切换**。

所以结论是：**没有条件的过渡，就是在动画播完后再切换。**

---

## 规则二：有条件的过渡，可以提前打断

你从行走瞬间切回待机，能提前打断，是因为：
- 那个"行走→待机"的过渡，**没有勾选 `Has Exit Time`**（或者退出时间设为了 0）
- 同时，它的条件（比如 `Speed` 小于 0.1）被满足了
- Unity 的规则是：**每一帧都检查条件。一旦条件满足，且没有退出时间限制，就立刻打断当前状态，开始过渡到目标状态**

过渡面板里有一个 `Exit Time` 参数：
- 如果设为 0，表示动画从第 0 秒开始就可以被条件打断
- 如果设为 0.8，表示动画必须播到 80% 之后，条件才会被"放行"，允许打断

---

## 规则三：循环动画 + 无条件过渡 = 永远循环的陷阱

如果一个动画：
1. **勾选了循环播放**（Loop Time）
2. 只有一个**无条件的过渡**到下一个状态
3. 这个过渡**勾选了 `Has Exit Time`**

那么：
- 动画永远在循环播放，**永远没有"播放完毕"的那一帧**
- 因为有 `Has Exit Time`，它必须等"播放完毕"才能切换
- 结果是：**永远卡死在这个状态，永远无法切换到下一个状态**

这就是为什么要**取消循环播放**的原因：
- 取消了循环，动画就有了明确的结束点
- 动画播到最后一帧，`Has Exit Time` 的条件就被满足了
- 于是自动触发那个无条件的过渡，切换到下一个状态（比如默认状态）
- 动画只播放一次就跳走，完美实现了"单次动画"效果

---

## 完整决策树逻辑

当一个过渡被评估时，Unity 按这个优先级判断：

```
1. 条件是否满足？
   ├── 不满足 → 不切换，继续保持当前状态
   └── 满足 → 进入第 2 步

2. 是否勾选了 Has Exit Time？
   ├── 没勾选 → 立刻打断当前动画，开始过渡
   └── 勾选了 → 进入第 3 步

3. 当前动画是否已播到 Exit Time 指定的时间点？
   ├── 还没播到 → 不切换，继续播放
   └── 已播到 → 开始过渡

4. 如果当前动画是循环的，且 Has Exit Time 勾选了？
   └── 动画永远不会"播完"，Exit Time 永远无法达成
       → 永久循环，无法切换（常见陷阱！）
```

---

## 实际应用建议

| 场景 | Has Exit Time | Loop Time | 说明 |
| :--- | :---: | :---: | :--- |
| 待机→行走 | ❌ 取消 | ✅ 勾选 | 按方向键立刻切换，行走持续循环 |
| 行走→待机 | ❌ 取消 | ✅ 勾选 | 松开按键立刻停下 |
| 攻击动画（单次） | ✅ 开启 | ❌ 取消 | 完整播放一次攻击动作后回到待机 |
| 受击动画（单次） | ✅ 开启 | ❌ 取消 | 播放完受击动画后自动切换回待机 |

这套逻辑是设计角色动作、UI 动效的基础。掌握之后，你就可以随心所欲地设计动画的打断、连招以及单次特效了。
